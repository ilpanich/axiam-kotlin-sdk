verifySet

suspend fun verifySet(set: String): SecurityEvent

Verifies one compact SET (CONTRACT.md §32.7), in this order, refusing at the first failure with the SetFailureReason in brackets:

  1. three base64url parts, a JSON-object header and payload `malformed`;

  2. typ secevent+jwt or application/secevent+jwt, any case `invalid_type`;

  3. alg exactly EdDSA `invalid_key`;

  4. the kid in the configured JWKS (cached for JWKS_CACHE_LIFETIME) — on a miss, ONE refetch, at most once a minute `invalid_key`;

  5. the Ed25519 signature `invalid_key`;

  6. iss equal to the configured issuer `invalid_issuer`;

  7. aud equal to, or an array containing, the audience `invalid_audience`;

  8. no exp, no sub; a non-empty jti, a numeric iat, an object sub_id; events with exactly one member `invalid_request`;

  9. a jti not seen within the replay window `replayed` — recorded only once steps 1–8 passed.

A SET that verifies has been recorded: verifying it again is replayed. Acknowledge a polled SET once you have processed it.

Answering a push (RFC 8935): 202 on success; on a refusal, 400 with {"err": e.failureReason.pushErrorCode()}.

Return

the verified event

Parameters

set

the compact SET

Throws

SetVerificationError

when the SET is refused

NetworkError

when the JWKS could not be fetched, or the ReplayStore could not answer (it threw) — neither is a verdict on the SET, which stays unjudged and unrecorded (CONTRACT.md §34.2 P3, P4)
