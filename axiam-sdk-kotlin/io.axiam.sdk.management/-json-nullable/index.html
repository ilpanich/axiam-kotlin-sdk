JsonNullable

@Serializable(with = JsonNullableSerializer::class)
sealed interface JsonNullable<out T>

A member where an explicit JSON null is a different statement from an absent member — CONTRACT.md §27.4 rule 5's "null is not absent".

Kotlin's own T? has two states, and a sparse body needs three: Absent (the member is not sent, and the stored value is kept), Null (the member is sent as null, which CLEARS the stored value) and Value (it is sent and replaces the stored value). Decoding keeps the same three apart, so a response that carried "next_credential_id": null is told from one that left the member out.

Used only where the contract names the distinction — today UpdateDirectoryConfig.groupBaseDn / groupFilter (§30.2) and SamlIdpInfo.activeCredentialId / nextCredentialId (§29.8 test 8). Every other optional member stays a plain T?, where null means absent.

// Clears the group filter; leaves everything else as stored.
client.directory.update(UpdateDirectoryConfig(groupFilter = JsonNullable.Null))
