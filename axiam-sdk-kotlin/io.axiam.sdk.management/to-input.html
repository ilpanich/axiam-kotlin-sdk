fun SsfStream.toInput(): SsfStreamInput

The ssf.update_stream body that re-states this stream (§32.2) — the plain converter. To edit a stream you read, use toInput with changes instead.

authorizationHeader and clearAuthorizationHeader are absent: absent keeps the stored header — unless the update moves endpoint_url to another origin, which needs one or the other (§32.3 rule 5).

The body carries the events_requested and the expected_updated_at that were read (contract 1.61). An events_requested of [] (the receiver's "none") stays [] — omitting it would reset the stream to every allowed event — and expected_updated_at is the response's own string (SsfStream.updatedAtRaw, contract 1.62), never the parsed instant rendered again, so the write lands only on the version that was read and is otherwise 409 (the receiver's own writes included): reload and retry.

The caller's duty (§32.2, contract 1.62). This converter sends the stream back as read; it cannot know that you are about to lower eventsAllowed. If you lower it with copy(), cutting eventsRequested to the new eventsAllowed is yours to do, in the same call: a requested list left outside the new ceiling is refused 400, and one left out altogether resets the stream to every allowed event (the three meanings of events_requested: absent resets, [] is none, a list is stored as given). toInput with changes does the cut for you. Set expectedUpdatedAt to null to replace whatever is stored: null is "none" and the key is left out.

Return

the replacement body

fun SsfStream.toInput(changes: SsfStreamChanges): SsfStreamInput

The ssf.update_stream body for this stream with changes applied — the change-taking read-modify-write form (§32.2, contract 1.62; §27.4 rule 5). Use it instead of toInput with no changes whenever you edit a stream you read.

What the body carries, and why each point is a rule rather than a convenience:

  • events_requested, as read. An update that omits it resets the stream to every event of events_allowed, widening what the receiver narrowed. The list that was read goes back as it was; an [] (the receiver's "none") goes back as [] and is never omitted.

  • Cut to the new ceiling. When changes lowers eventsAllowed and does not name eventsRequested, the requested list becomes the entries of the list read that are in the new ceiling, in their order (a request outside the ceiling is 400). An eventsRequested named in changes is sent as given: the server judges it.

  • expected_updated_at, as read — the server's own string (SsfStream.updatedAtRaw), byte for byte, not the parsed instant rendered again. The update then lands only on the version you read, and a write made since (the receiver's own included) answers 409 (a io.axiam.sdk.errors.ConflictError, never retried): read again and decide again. JsonNullable.Null in changes is "none": the key is left out of the body and null is never sent.

authorizationHeader and clearAuthorizationHeader are absent unless changes names them (absent keeps the stored header, §32.3 rule 5).

Return

the replacement body
