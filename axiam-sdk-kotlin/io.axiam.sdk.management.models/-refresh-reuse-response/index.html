RefreshReuseResponse

@Serializable(with = RefreshReuseResponse.Companion.Serializer::class)
enum RefreshReuseResponse : Enum<RefreshReuseResponse>

What the token endpoint does when a refresh token that has already been rotated is presented again and refused (G-C, #818 — the T-254 amendment). Two values, ordered by strictness: * revoke_session — the default (D-N2). The refusal also invalidates the session the replayed token names (which publishes to the revocation feed) and revokes every refresh token issued under that session — whichever client it was issued to, the console sign-in included, with no back-channel logout sent — as the authorization-code replay path does for a code (RFC 6749 §10.5; OAuth 2.0 Security BCP §4.14.2). Only a presentation by the token's own client, passing the token's sender constraint, triggers it (#821). On a client with no grace window the honest holder of a replayed token has nothing left to lose — its token is already dead and it never received the successor — so the revocation costs it nothing and costs whoever holds the successor everything. * refuse — the 1.1.x behaviour: the presentation is refused, marked on the session and audited, and nothing else is revoked. Neither value changes what is accepted. A fapi2 client's presentation inside the grace window is accepted and marked whatever this says (D-N4); a token revoked at logout is not a replay and revokes nothing. This text is published as the schema's description in sdks/openapi.json, so it carries no rustdoc intra-doc links (F4-W1-08, #824).

Each constant carries the spelling the server uses on the wire, so the Kotlin name can follow Kotlin's conventions without changing what is sent.

An open enum. A value this SDK's copy of the spec does not list decodes to RefreshReuseResponse.UNKNOWN rather than failing the response it arrived in (CONTRACT §27.11 rule 1). UNKNOWN is never sent: carrying it back into a write is refused locally, before any request, because the SDK MUST NOT send a value it does not know (CONTRACT §34.2 P12.2) -- never written as an empty string for the server to refuse. Rendering it (toString) never fails. A when over these constants needs an UNKNOWN branch.
