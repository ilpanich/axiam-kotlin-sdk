ConflictError

class ConflictError @JvmOverloads constructor(message: String, val reasonCode: String? = null) : AuthzError

A §27 management operation collided with the state already there (HTTP 409): a name already taken, a certificate already revoked, a role that already holds the grant.

A SUB-TYPE of AuthzError, not of NetworkError. §2 already maps 409 to AuthzError as "resource-level access denied", and CONTRACT.md §27.4 rule 7 keeps that mapping rather than re-deciding it — the sub-type exists to give the caller something to act on, not to move the status.

Never retried: a conflict is the server telling the truth, not a transient fault, and repeating the request cannot change it (§27.4 rule 8).

reasonCode (contract 1.62, §36.4): the network operations name which conflict a 409 is in a reason_code member beside error (stale_version, strands_profile, has_children, duplicate_vlan, profile_exists, …). It is surfaced verbatim: the vocabulary is open (§36.3 rule 2), so a value this SDK has never seen arrives as the string the server sent, and null means the body carried none (a server that predates it, or an operation that does not name one). Branch on it, never on the message — which an SDK does not parse and a caller must not either. It is not the reason of an authorization decision (§3).
